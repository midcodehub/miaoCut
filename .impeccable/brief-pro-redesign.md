# 会员模块重新设计：设计说明（shape 产出）

> 2026-10-11。依据：PRODUCT.md、DESIGN.md、`.impeccable/critique/` 里的首轮评审（17/40）。
> 本文件只定“做什么、怎么运作”，不含代码；视觉规范一律以 DESIGN.md 为准。

## 1. 用户与场景

- **主角：电商卖家**。主要在电脑前，手里有 20–200 张商品图急着上架。
  - 来路：免费单图工具的「批量处理」按钮、每日免费额度用尽弹窗、顶栏「定价」。
  - 心态：想先确认两件事，**效果能不能直接上架**、**一批要花多少钱**。
- **回访用户**：已注册，直接进批量页干活，或者充值、订阅后回账户页确认到账。

## 2. 成功标准与可用证据

- **成功**：第一次来的卖家在批量页看懂“上传一批 → 拿回一批可直接上架的图 → 只为成功的图付费”，然后用 Google 一键登录拿到 100 积分，跑完第一批并下载。
- **可用证据**：
  - `examples/*.webp` 处理前后示例；
  - 计费规则（失败不扣）；
  - 批量文件 24 小时删除；
  - MIT 开源。
- **不得编造**：用户数、评价、案例。
- **竞品说不出、我们能说的**：
  - 单图永久免费；
  - 批量只为成功付费、失败自动返还；
  - 输出直接符合平台要求（白底 / 方图 / JPG）。

## 3. 方向

- **视觉**：沿用 DESIGN.md「安静的工作台」，不另起视觉体系。批量页弃用独立 CSS，改用全站 Tailwind、顶栏、页脚，并支持深色模式。
- **结构**：**批量页 = 门面 + 工作台**。同一个 URL 按状态切换：
  1. **未登录（门面）**：
     - 首屏就是工作台本身：大上传区，加一组示例商品图的处理前后对比（棋盘格背景）。
     - 三条要点：新用户送 100 积分 ≈ 100 张、每张低至 $0.010、失败不扣。
     - 登录区：Google 为主，邮箱链接为辅。
     - 用户可以先把图拖进来，图暂存在浏览器本地（IndexedDB），登录回来后还在。
  2. **选图（已登录）**：
     - 处理档位：「标准」1 积分；「精细边缘（毛发、毛绒、植物）」2 积分。
     - 输出预设：透明 PNG / 白底 JPG / 白底方图（如 2000×2000）。
     - 已选文件：可以逐张删除，也可以全部清空。被跳过的文件要明确说明原因。
     - 预计消耗和余额并排显示；余额不足时，就地提示购买积分或订阅。
  3. **处理中**：
     - 显示进度条和缩略图网格。
     - 任务 ID 记在本地，刷新或离开后回来能继续看进度。
  4. **结果审阅**：
     - 大缩略图，放在棋盘格背景上；点开可以前后对比。
     - 失败的图写明原因，提供「重试失败的 N 张」，失败本来就不扣分。
     - 支持 ZIP 打包下载，也支持单张下载。
     - 显示结果的保留期限。
- **输出预设的实现**：GPU 仍然只返回透明图。白底、方图、JPG 在浏览器里打包时合成，复用单图编辑器的引擎，**不改后端**。
- **定价页**：只负责“比较和购买”。
  - 订阅三档为主，一次性积分包为辅（“不想订阅？买一次性积分包”）。
  - 单张价格作为主信息。
  - 附简短常见问题：积分是什么、两档区别、结转规则、有效期、退款。
- **账户页**：
  - 余额拆成两部分：订阅积分（何时重置、可结转多少）和充值积分（到期日）。
  - 显示订阅状态，提供管理入口（Stripe 客户门户：改档、取消、发票）。
  - 流水按批次合并成一行，例如“批量 24 张：成功 23，扣 23”。
- **入口统一**：
  - 首页按钮去掉 “Pro” 徽章，提示改为“最多 200 张”。
  - 额度弹窗文案与批量页一致。
  - 登录只保留一个组件，批量页和账户页共用。

## 4. 订阅方案（2026-10-11 确认）

| 档位 | 每月积分 | 价格 | 每张成本 |
|---|---|---|---|
| Basic | 300 | $6.99/月 | $0.023 |
| Pro | 1500 | $19.99/月 | $0.013 |
| Business | 5000 | $49.99/月 | $0.010 |

- **结转**：未用完的订阅积分结转到下个月，最多结转一个月额度。
- **扣分顺序**：先扣订阅积分，再扣充值积分。现有逻辑已支持。
- **权益只写现在能做到的**：
  - 每张更便宜；
  - 结果保留 7 天（非订阅用户 24 小时）；
  - 单批上限更高（Pro / Business 500 张，见第 7 节）。
- **不写**：团队席位、API、优先队列。这些没做，不出现在页面上。
- **积分包保持不变**：100 / 500 / 1500 / 5000，12 个月有效。

## 5. 状态与数据范围

- **张数**：0 / 1 / 典型 20–80 / 上限 200（订阅档可能更高）。
- **余额**：0 / 不足以完成本批 / 足够。
- **订阅状态**：无 / 生效中 / 续费失败（past_due）/ 已取消但本期仍有效。
- **处理结果**：全部成功 / 部分失败 / 全部失败；处理中途刷新。
- **异常**：登录服务不可用；网络中断；上传失败。
- **手机端**：批量以桌面为主，但手机上要能完成登录、查看结果、购买和订阅。

## 6. 约束

- 纯静态 HTML + Tailwind + 原生 JS；中英文（`pro-i18n.js`）；深色模式；必须达到 WCAG AA 对比度。
- 订阅需要新的后端工作：
  - Stripe 订阅价格 3 个；
  - webhook：`invoice.paid` 按结转规则发积分，`customer.subscription.updated/deleted`；
  - Stripe 客户门户；
  - 数据库加订阅字段和结转逻辑；
  - 7 天保留需要 R2 按前缀设置生命周期规则。
- 以上涉及线上服务的改动，**到时逐项先问用户**。

## 7. 开发顺序与已定细节

- **开发顺序**：
  - **5a**：批量页重建（门面 + 工作台 + 结果审阅 + 输出预设）。纯前端，可以先上线。
  - **5b**：定价页 + 账户页（积分包部分）+ 入口统一。
  - **5c**：订阅后端 + 订阅界面（定价页订阅档、账户页订阅管理）。
- **已定**：单批上限 非订阅 / Basic 200 张，Pro / Business 500 张；未登录先拖图、登录后保留（IndexedDB）要做。
